# Контекст проекта для AI-агентов

## Назначение

Aurora AI Hub — нативное приложение для ОС Аврора, управляющее локальными GGUF-моделями и предоставляющее чат и API другим приложениям. Цель — офлайн-инференс на устройстве, без облачного backend.

## Проверенный статус

- Aurora SDK 5.2.1.200 MB2; эмулятор x86_64.
- CMake/RPM собирается; приложение устанавливается и запускается в эмуляторе.
- Есть каркас QML-страниц моделей, каталога, чата, настроек.
- Работа `llama.cpp`, реальный ответ модели, загрузки GGUF, межприложенческого API **не подтверждена**.
- За актуальным состоянием обращайтесь к `docs/STATUS.md` и merged PR; не считайте план реализованным кодом.

## Стек и принципы

C++/Qt 5, QML/Qt Quick, Sailfish Silica, CMake, Qt Network, QProcess, Qt D-Bus (кандидат для IPC), RPM. Локальный движок: `llama.cpp` / `llama-server` (исследуется). Модульный монолит; UI не должен напрямую управлять системными процессами или сетевыми запросами.

## Структура и владельцы

- `qml/modules/**` — UI, владелец: участник 1.
- `core/inference/` — AiClient, владелец: участник 1.
- `core/runtime/` — RuntimeManager, llama.cpp, владелец: участник 2.
- `core/models/` — ModelManager, импорт/скачивание, владелец: участник 3.
- `integrations/dbus/`, `examples/smart-notes/` — IPC и демо, владелец: участник 4.
- `tests/`, RPM/CI, совместимость — владелец: участник 5.

## Предполагаемые интерфейсы

- `ModelManager`: список, импорт, скачивание, проверка файлов GGUF.
- `RuntimeManager`: запуск/остановка процесса, порт, состояние, ошибки, ограничения ресурсов.
- `AiClient`: HTTP-запросы к локальному runtime, обработка SSE/потокового вывода, отмена.
- IPC API: межприложенческий вызов функций; транспорт выбирается после прототипа с учётом Sailjail.

Это контракт для обсуждения, а не утверждение, что классы уже реализованы.

## Правила для AI-агентов

1. Перед изменениями изучите `CMakeLists.txt`, существующие файлы и `docs/STATUS.md`; не придумывайте API и пути.
2. Не меняйте без необходимости пакетный идентификатор `ru.auroraaihub.aurora_ai_hub`, desktop-файл и имена RPM-ресурсов. Исходный корневой QML-файл называется `qml/aurora-ai-hub.qml`.
3. Используйте Qt 5 / Sailfish Silica; не добавляйте зависимости без обсуждения.
4. Соблюдайте границы модулей; внешние интерфейсы согласуйте через Issue/PR.
5. Не утверждайте, что функция работает, пока нет подтверждённого теста в Aurora OS.
6. Не коммитьте build-каталоги, `*.user`, модели `*.gguf`, токены и секреты.
7. В PR укажите изменения, способ проверки, риски, связанные Issues. При изменении функциональности обновите `docs/STATUS.md`.
8. Для C++/QML предпочтительны ясные небольшие изменения. Комментарии в коде пишите с маленькой буквы.

## Перед началом работы

Прочитайте `README.md`, `docs/ROADMAP.md`, `docs/STATUS.md`; проверьте открытые Issues и текущую ветку. При расхождении документов и кода источником истины является код и воспроизводимые результаты тестов; исправьте документацию в том же PR.
